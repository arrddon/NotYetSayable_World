# Not Yet Sayable: Latent Homes

V05의 웹 아카이브. 무료 정적 호스팅을 위한 HTML/CSS/JavaScript로 구성한다. 브라우저는 공개 JSON과 지도 타일을 읽으며, 탐색 중 원본 DB나 AI를 호출하지 않는다. 로컬 전시 서버의 비공개 발행기가 완료 기록을 공개 JSON으로 변환한다.

2026-10-26 정리 기준 주요 구현은 완료·운영 단계다. 전체 설치의 실행 순서·역할·복구는 V05 작업공간의 `handoff/FINAL_OPERATIONS.md`에 정리했다. 이 README는 지도 앱의 실행·설정 기준이다.

## 현재 동작

- MapLibre + OpenFreeMap의 지명 없는 청색 단색 도로·물길 평면지도와 파티클 효과. 실제 건물 형상은 렌더링하거나 샘플링하지 않는다.
- 전체 너비 지도에 더 밝고 포화된 코발트·시안·화이트를 사용한다. 군집 영역은 낮은 불투명도의 바닥 흔적 위에 촘촘한 GPU 입자 지형을 쌓고, 입자의 위치·높이·크기·밝기를 움직인다. 실제 참여자 경계를 측정한 영역이 아니다.
- 보이는 개별 포인트와 군집마다 빛기둥을 세운다. 큰 대상의 주요 기둥은 더 굵고 길며 대각선으로 기울어 화면 밖까지 이어진다. 현재 지도 화면의 명암을 내부에서 반전하고 금속성 하이라이트와 흐르는 입자 질감을 더한다. 노란색·금색은 없다. 장식 수와 참여자 수는 구분하며 집계 알고리즘은 유지한다.
- 지도 조작 UI는 Pretendard, 우측은 시스템 고정폭 글꼴의 무채색 콘솔 형태다. 좌상단 제목·부제·도시 메뉴·About은 제거했다. 전체 지도 보기는 좌하단 지구 아이콘으로 제공한다.
- 지도 전용 bloom·그레인은 전체 화면에 적용한다. 우측 fade와 비네트는 제거했고 HTML 글자는 후처리에서 제외한다. 정지 지도의 입자는 rAF 기준 최대 30fps로 갱신하며 숨김 탭·지도 이동 중에는 추가 repaint를 멈춘다.
- 우측 상단 `[graphics]`: 9개 실시간 파라미터, 초기화와 설정 JSON 복사. 인디케이터 길이·수, 영역 질감·퍼짐을 조절한다. 기본값은 2026-10-22 사용자 첨부 이미지 기준이다. 조절값은 현재 브라우저에만 저장하며 공개 아카이브를 수정하지 않는다.
- 확대·축소·세계 보기·지리적 군집 선택. 기존 city/unitId 메시지 이동은 유지한다.
- 화면 영역 / 선택 군집의 공통 주제·키워드 집계.
- 콘솔 텍스트를 지도 위에 직접 오버레이한다. 지역명은 16px, 대표 키워드·주제 필터·나머지 키워드는 12px다. 주제별 막대는 3px, 첫 행의 채움은 4px다. 텍스트 뒤 배경·blur는 없고 모바일도 우측에 좁게 겹친다. 따옴표·쉼표·대괄호를 사용하며 중간의 흰색 선 차트는 주제별 참여자 비율(0–1)과 필터다. AI confidence나 Bayesian prior가 아니다. 별도 카테고리 제목·정보 스크롤은 없다.
- UI·키워드·접근성 레이블은 영어 고정이다. 각 키워드는 대표 영역과 나머지 목록을 합쳐 한 번만 표시한다. 짧은 목록은 정지하고 긴 목록만 넘친 높이 안에서 천천히 왕복하며 hover/focus로 멈춘다. 줌·위경도·지도 조작은 좌측 하단에 모은다.
- 공개 manifest 30초 확인. 새 버전이 있을 때만 새 데이터 수신, 검증 성공 후 교체. 자동 갱신으로 카메라를 초기화하지 않는다.
- 배경 지도 연결 실패 시 키워드 탐색 유지. 갱신 실패 시 마지막 정상 데이터 유지.

**2026-10-22 Git 동기화 시점의 공개 스냅샷은 실제 완료 기록 205건**이다. 최초 연결한 196건(7월 81건, 9월 115건)에 신규 완료 기록 9건이 자동 반영됐다. 이후 현재 건수는 활성 manifest의 recordCount를 따른다. 지도 핀은 미래에 살고 싶은 곳이다. 원문·번역 전문·손글씨·trace·분류 이유·confidence·세션 정보·비밀키는 공개 파일에 포함하지 않는다. 원래 unit ID를 보존하며 하나의 기록이 같은 키워드를 시간대마다 반복해도 한 번만 집계한다. 고유 인원수와 완료 참여 횟수를 혼동하지 않는다. 합성 302건 파일은 개발용 fixture로 보존하지만 활성 manifest는 실제 아카이브를 가리킨다.

2026-10-26 완료 목록을 다시 조회한 현재 공개 스냅샷은 `live-927218f3621268c919dd8a36`의 **210건**이다. 기존 205건에 이후 완료 기록 5건을 더한 데이터와 manifest를 이번 V2 아카이브에 포함한다. `synthetic: false`, manifest/JSON 버전·건수 일치와 공개 허용 필드를 확인했고 `npm run check`의 34개 검사가 통과했다.

현재 지도 웹은 **Web V2** 기준으로 보관한다. Git 태그는 `web-v2-20261026`이며 [WEB_V2_ARCHIVE.md](WEB_V2_ARCHIVE.md)에 범위와 복원 방법을 기록했다. 운영·문서가 참조하는 `latent-homes-web/` 경로는 유지한다. 새 비주얼·인터랙션 웹은 후속 논의 대상이다.

## 4K 출력과 카메라

4K 전체화면에서도 HTML 글자와 조작 UI는 화면 해상도로 표시한다. 지도 framebuffer만 최대 2560×1440에 해당하는 3,686,400 pixel로 제한한다. 3840×2160 / DPR 1에서는 내부 2560×1440으로 약 56% 적은 pixel을 처리한다. 작은 화면은 기존 최대 DPR 1.25를 유지한다. 크기 변경은 120ms 병합 후 GPU 버퍼를 조정한다.

정지 지도 애니메이션은 requestAnimationFrame 기준 최대 30fps로 요청하며, 숨김 탭·이동 중에는 추가 repaint를 요청하지 않는다. 실제 달성 FPS는 GPU와 함께 실행 중인 TD/브라우저에 따라 달라진다. 같은 범위의 키워드 DOM·선택 필터를 반복 생성하지 않고, 지도 입자의 지역 투영값은 카메라/지역 변경 때만 계산한다. 영역 바깥 입자는 윤곽의 삼각함수 계산을 건너뛴다. GPU 입자 수와 실제 기록 집계는 유지한다.

지도는 북쪽을 위로 고정한다. 기본 도시 bearing, 마우스·터치·키보드 회전, 방향 초기화 버튼을 제거했다. LAN에서 예전 카메라 상태를 받아도 bearing은 0으로 정규화한다. 확대에 따른 자동 pitch는 유지한다. 지도와 지도 후처리의 청색은 조금 더 울트라마린 쪽으로 조정했다.

## iPad 조작 → TD → 외부 모니터

PC와 iPad를 같은 네트워크에 연결한 뒤, 이 폴더에서 실행한다. 추가 패키지 설치는 없다.

```powershell
npm run exhibition
```

Windows에서는 `START_EXHIBITION.cmd`를 더블클릭해도 된다. 실행 창은 전시 중 열어 둔다. 이미 실행 중이면 새로 실행하지 않는다.

**TD를 실행하는 것만으로 이 서버가 시작되지는 않는다.** Node 전시 서버를 먼저 별도로 실행한 뒤 TD가 출력 주소를 불러온다.

서버가 출력하는 두 주소를 사용한다.

| 기기 | 주소 | 역할 |
| --- | --- | --- |
| iPad Safari | `http://<PC의 IPv4 주소>:4180/?mode=control` | 지도 탐색·주제/군집/기록 선택·그래픽 조절 |
| TD Web Render TOP | `http://127.0.0.1:4180/?mode=display` | 최신 상태를 받아 PC에서 렌더링 |

2026-10-22 이 PC에서 확인한 iPad 주소는 `http://10.80.110.88:4180/?mode=control`이다. 네트워크가 바뀌면 실행 창에 표시되는 현재 주소를 사용한다. iPad의 `127.0.0.1`은 iPad 자신을 가리키므로 PC 주소를 넣어야 한다.

### 처리 역할

| 구성 | 담당 처리 |
| --- | --- |
| iPad의 `mode=control` | 지도 미리보기 렌더링·조작. 카메라·선택·집계 범위·그래픽 값을 HTTP POST로 전송 |
| PC의 Node 전시 서버 | `dist/` 웹 파일 제공, 상태를 메모리에 보관하고 SSE로 중계, 완료 아카이브의 공개 JSON 동기화 |
| PC의 `mode=display` | TD Web Render TOP 내부 브라우저에서 웹 코드를 실행하고 PC GPU로 최종 지도·입자·빛기둥·키워드를 렌더링 |
| TD | 웹 렌더링 결과를 TOP 영상으로 받아 합성하고 모니터에 출력 |

전송하는 것은 조작 상태이며 iPad 화면 영상이 아니다. 출력 페이지도 같은 `index.html`과 모듈을 사용하고 query로 역할을 정한다. 지도 그래픽 로직은 JavaScript/WebGL에 있다. 일반 `/` 페이지는 독립 탐색이다. `mode=display`의 실시간 수신은 PC의 loopback 접속만 허용한다.

기존 관객 촬영·분석용 Python 브리지와 휴대폰 참여 WebApp은 별도 경로다. 이 전시 서버 실행이 기존 브리지의 시작·세션 연결을 대신하지 않는다.

### TD에서 사용자가 설정할 값

1. `Web Render TOP` 하나를 만들고 **URL or File**에 `http://127.0.0.1:4180/?mode=display`를 넣는다.
2. Common → Output Resolution을 **Custom Resolution**, Resolution을 우선 **1280 × 720**으로 설정한다. 동작 확인 후 실제 모니터 해상도와 TD 라이선스 한도에 맞춘다. **DPI Scaling Factor = 1**, **Maximum Render Frame Rate = 30**, **Active = On**으로 시작한다.
3. Web Render TOP 뒤에 `Null TOP`을 연결한다. 예: `webrender1 → null_web`.
4. `Window COMP`의 **Window Operator**에 `null_web` 경로를 지정한다. **Justify and Offset to = Specify Display**, **Display = 실제 외부 모니터**, **Opening Size = Fill Location**, **Borders = Off**, **Cursor Visible = Never**로 설정한다.
5. **Open as Perform Window**로 출력한다. Windows 디스플레이 설정은 **확장**으로 둔다. 외부 모니터 번호는 PC마다 다르므로 직접 선택한다.

공식 파라미터: [Web Render TOP](https://derivative.ca/UserGuide/Web%20Render%20TOP), [Window COMP](https://docs.derivative.ca/Window_COMP). 에이전트는 TD 노드·.toe를 편집하거나 저장하지 않았다. 실제 TD의 WebGL2 효과·출력 해상도·지속 프레임 성능은 현장에서 확인해야 한다.

### 동작과 복구

- 지도 위치·줌·방향·pitch·FOV, 주제, 선택한 공개 기록 ID, 그래픽 9개 값을 보낸다. iPad와 출력 화면의 비율이 달라도 동일한 기록 집합을 집계해 키워드·주제 비율이 일치한다. 화면에 보이는 지도 범위와 장식 픽셀은 해상도에 따라 다를 수 있다.
- 도로·물길의 실제 바탕 지도를 유지한 채 입자를 겹친다. `map-particles.mjs`가 원래 지도를 지우고 전체 화면을 격자로 바꾸던 처리는 2026-10-22 사용자 화면 확인 후 제거했다. 적용할 때 iPad는 새로고침하고 TD Web Render TOP은 **Reload Current Page**를 누른다.
- 출력 모드는 지도/그래픽 조작을 숨기고 입력을 받지 않는다. 키워드·주제·데이터 상태 표시·지도 출처는 유지한다.
- 추가 라이브러리 없는 HTTP POST + SSE 연결이다. 변경된 상태를 최대 초당 10회 보내고 출력 카메라는 짧게 보간한다. 영상은 PC가 직접 그린다.
- 조작 화면은 동시에 하나만 활성화된다. 두 번째 조작 탭은 대기한다. 첫 탭을 닫으면 넘겨받으며, 연결이 갑자기 사라지면 약 7초의 점유 만료 후 다른 조작 탭이 연결할 수 있다.
- 연결이 끊기면 마지막 화면을 유지한다. 출력의 새로고침·재접속 시 서버가 최신 상태를 다시 보낸다. 상태는 서버 메모리에 있고 서버/PC 종료 뒤 영구 보관하지 않는다. 서버만 재시작하고 iPad가 계속 열려 있으면 현재 조작 화면을 다시 보낸다.
- Safari를 전면에 두고 iPad 자동 잠금을 꺼 두면 조작 연결을 유지하기 쉽다. 서로 다른 아카이브 버전이면 적용을 대기하며 공개 manifest의 기존 30초 갱신으로 같은 버전을 기다린다.
- 기존 `npm run dev`는 **127.0.0.1:4173** 정적 미리보기로 유지한다. 일반 `/` 방문은 독립 탐색이며 전시 화면을 바꾸지 않는다. 이번 LAN 기능은 공통 계약 C1의 `mode=td`, V4 WebSocket 9982, 완료 이벤트와 별개다.

### iPad에서 접속이 안 될 때

PC 브라우저에서 `http://127.0.0.1:4180/`가 먼저 열리는지 확인한다. 이어 실행 창의 IPv4 주소로 접속한다. iPad에서만 접속이 안 되면 Windows 방화벽에서 **Node.js / TCP 4180**의 현재 네트워크 인바운드 허용을 확인한다. 게스트 Wi-Fi나 공용 Wi-Fi의 기기 간 통신 차단이 있으면 기기 간 통신이 가능한 공유기/핫스팟을 사용한다. 지도 타일에는 인터넷이 필요하다. 이번 구현은 방화벽·공유기 설정을 자동 변경하지 않는다.

서버는 `Ctrl+C`로 종료한다. 4180이 사용 중이면 기존 서버를 사용하거나, 다른 포트를 지정한 뒤 두 기기의 주소도 함께 바꾼다.

```powershell
$env:EXHIBITION_PORT = '4181'
npm run exhibition
```

## 그래픽 파라미터

정의·범위·기본값은 `dist/graphics.mjs`, 패널은 `dist/graphics-panel.mjs`에 있다. 세부 설정은 `nys-graphics-v2` localStorage에 저장된다. 이전 v1 설정 대신 새 기준으로 시작하고 이후 조절값을 저장한다. 손상된 값은 기본값으로 대체하고 수치는 범위 안으로 제한한다. 사용자 첨부 이미지의 기본값:

| 파라미터 | 기본값 | 조절 범위 |
| --- | --- | --- |
| 인디케이터 길이 | 2.8× | 0.4–2.8× |
| 인디케이터 밀도 | 2.0× | 0.4–2.0× |
| 군집 퍼짐 | 0.80× | 0.5–2.0× |
| 빛 번짐 강도 | 1.40× | 0–4.0× |
| 빛 번짐 반경 | 1.1× | 0.5–3.0× |
| 사이언 비율 | 0% | 0–100% |
| 도로 입자 밀도 | 1.5× | 0.4–1.5× |
| 영역 질감 | 1.7× | 0.4–2.0× |
| 그레인 | 8.0% | 0–10% |

카메라는 저장 파라미터가 아닌 자동 시점이다. 도시 탐색의 pitch 52°는 유지하고 줌 14–18 구간에서 부드럽게 40°로 줄여 최대 확대에서 더 내려다본다. 데스크톱/모바일 FOV 48°/50°는 유지한다.

Bloom은 밝기를 그대로 더해 하얗게 잘라내는 대신 지수 곡선으로 합성한다. 높은 강도에서도 빛기둥 사이의 차이를 최대한 유지한다.

길이·밀도·질감·퍼짐 변경은 140ms 병합 후 군집 그래픽을 다시 만든다. 표면 입자는 데스크톱 최대 48,000개/모바일 18,000개, 인디케이터는 최대 256개/160개다. Indicator density 기본값 2에서 보이는 포인트와 군집 각각에 기둥을 만들며, 작은 값은 적용 비율을 낮춘다. 화면 밖 앵커는 40px 여유를 두고 생략한다. 주요 6개/3개 기둥은 이전보다 길이 약 1.5배·두께 1.28배로 강조하고, 나머지는 가는 기둥으로 채운다. 지도 픽셀 overlay는 180,000개/42,000개 상한을 사용한다. 인디케이터는 같은 완만한 기울기의 원통을 instanced draw로 그리고 저배율에서도 축소해 유지한다. 원통을 24분할로 줄이고 작은 기둥의 뒤쪽 벽 그리기를 생략하며, 주변 입자는 전체 최대 8,400개/1,950개를 기둥 수에 나누어 쓴다. 명암 반전은 지도 framebuffer 복사본을 사용한다. 애니메이션은 기존 버퍼의 셰이더 값만 바꾸며 매 프레임 DB·AI·타일 샘플링·입자 재생성을 하지 않는다.

지도와 공개 데이터를 병렬로 불러오고 경량 평면지도를 먼저 초기화한 뒤 GPU 효과를 등록한다. canvas는 전체 화면을 채우고 내부 해상도에는 위 4K 픽셀 상한을 적용한다. 별도 전체 스타일 JSON·글리프·스프라이트는 내려받지 않는다. 실제 첫 방문의 지도 타일 시간은 외부 네트워크와 캐시 상태에 따라 달라진다. 장시간 전시 GPU 성능은 현장 기기에서 확인한다.

## 실제 아카이브 연결

`scripts/archive-source.mjs`는 기존 Supabase의 읽기 전용 `archive_manifest` / `archive_get`만 호출한다. `scripts/publish-archive.mjs`는 허용된 필드만 추려 검증 후 버전 파일을 먼저 쓰고 manifest를 원자적으로 교체한다. 기존 완료 기록을 재업로드하거나 AI로 재분석하지 않는다. 하나라도 변환에 실패하면 부분 발행하지 않고 마지막 정상 아카이브를 유지한다.

서버 설정은 프로세스 환경 → 웹 폴더의 `.env.local` → V05 `system/.env.local` 순으로 `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`를 읽는다. 값은 서버 메모리에서만 사용하며 브라우저·Git에 넣지 않는다. 비공개 중간 원본은 저장하지 않는다. `.openai/local/`에는 source ID·완료 시각·공개 ID의 갱신용 캐시만 저장하고 Git에서 제외한다.

```sh
npm run archive:publish
npm run archive:watch
# 완료 시각을 유지한 채 기존 분석 결과를 정정한 경우 전체 재조회:
npm run archive:publish -- --force
```

`npm run exhibition`은 시작 시 한 번 동기화하고 이후 60초마다 완료 목록을 조회한다. **서버 코드를 수정한 뒤에는 실행 중인 전시 서버를 한 번 재시작해야 한다.** 이번 현장 서버는 버전 대기 문제 수정 후 재시작했다. 설정이 없는 다른 PC에서는 기존 공개 JSON을 그대로 제공한다. 최초 전체 조회 뒤에는 완료 목록의 source/ID/완료 시각을 비교해 새 기록·변경된 완료 시각의 기록만 가져온다. 목록이 같으면 개별 기록을 다시 조회하지 않는다. 같은 완료 시각을 유지한 내부 정정은 `--force`로 반영한다. 삭제는 다음 발행에서 제외한다.

서버는 현재 발행된 아카이브 버전을 조작기/출력에 알리고, 새 발행 시 SSE로 갱신을 알린다. 조작기는 예전 버전의 카메라·그래픽을 이어받고 현재 공개 데이터에 남아 있는 선택 ID만 보존한다. 지도 범위의 ID는 새 데이터에서 다시 계산해 보낸다. 예전 데모의 creativity/community 필터는 해제한다. 출력은 새 버전의 조작 상태를 기다리며, 서버는 이전 버전 상태가 최신 상태를 덮어쓰는 요청을 거절한다. 코드 교체 후에는 iPad를 먼저 새로고침하고 출력 크롬에서 Ctrl+Shift+R을 사용한다. 2026-10-22의 버전 대기는 수정/서버 재시작 뒤 사용자가 정상 동작을 확인했다.

브라우저/iPad/출력은 30초마다 작은 공개 manifest를 재검증하고 버전이 바뀔 때만 공개 JSON을 받는다. 로컬 전시는 정상 연결·발행 시 새 완료 기록을 통상 60+30초 안팎에 반영한다. 조회 시간·오류가 있으면 더 늦어질 수 있다. 화면 수가 늘어도 서버 쪽 DB 조회 주기는 늘지 않는다. 지도 이동에 따른 지도 타일 통신과 정적 파일 요청은 별도로 발생한다.

시간대는 Q1 → past, Q2 → present, Q3/Q3-1 → future다. 대표 주제는 미래 상상의 기존 Q3 `classification.primary_theme`를 사용한다. 실제 여섯 분류 Connection / Stability / Freedom / Care / Possibility / Belonging을 소문자 ID로 변환하고 confidence로 지지 수를 가중하지 않는다. 기존 영문 키워드만 재사용하며 `ko`는 빈 문자열로 두고 번역을 만들어 넣지 않는다. 키워드 ID는 공백·대소문자·일부 따옴표를 정규화한 영문에서 만들고 같은 키워드의 시간대 중복을 제거한다. 도시명은 기존 네 도시 반경 45km 안에서만 넓은 지역명으로 표시하며 역지오코딩을 호출하지 않는다.

공개 데이터는 `dist/data/manifest.json`과 해당 manifest가 가리키는 버전 파일로 구성된다. `schemaVersion: 1`, 문자열 `version`, `updatedAt`, `synthetic`, `locationMeaning: "desired-future-home"`, `records`를 사용한다. 한 레코드는 `id`, `position: [lng, lat]`, `theme`, `city`, `area`, `past`, `present`, `future`를 포함한다. 시간별 키워드는 `{id, ko, en}` 배열이다.

안전한 비공개 변환기에서 원본을 읽고 공개 가능한 필드만 새 버전 파일로 만든다. 새 데이터 파일과 manifest를 같은 배포에 포함한다. manifest의 `file`은 `data/archive.<version>.json` 형태다. 기존 파일 내용을 같은 버전 이름으로 덮어쓰지 않는다. 수정·삭제도 새 버전을 발행한다. 검증 실패나 배포 실패 시 마지막 정상 버전을 유지한다.

로컬 JSON 최신화와 온라인 배포는 별개다. 이 발행기는 Git push·Sites/Vercel 배포를 자동 실행하지 않는다. 온라인 사이트의 새 기록은 공개 JSON을 포함한 push/배포 후 보인다. PC가 꺼져 있으면 원본 DB 동기화가 대기하지만 이미 배포된 사이트는 계속 열린다.

`_headers`는 manifest의 재검증과 데이터 캐시를 설정한다. 호스팅 공급자의 경로 매칭 규칙에 맞춰 실제 적용을 확인한다. 사이트 탐색의 정적 파일 요청과 새 기록의 AI 처리·DB 저장은 별도 사용량이다.

## TD 네비게이션 준비

동일 origin의 임베디드 화면에서 다음 메시지를 받을 수 있다.

```js
frame.contentWindow.postMessage({ type: 'nys:navigate', city: 'seoul' }, location.origin);
frame.contentWindow.postMessage({ type: 'nys:navigate', unitId: 'LH-DEMO-0001' }, location.origin);
```

다른 origin의 TD 제어 브리지와 업로드 인증은 아직 연결하지 않았다. 서비스 역할 키를 브라우저에 넣지 않는다.
